# 实现计划与范围

目标：为 504 / 505 实验室实现中文设备展示、考试准入、审批预约、借还及管理后台。用户已授权先实现再按 issue 迭代。

架构：React + TypeScript + Vite，HashRouter 适配 GitHub Pages 子目录。前端支持显式 demo 与 Supabase 模式；生产数据由 PostgreSQL RLS、受控 RPC 和注册触发器保护。演示模式仅保存本浏览器，不作为多人系统。

1. 领域规则与测试：时间区间半开、仅北京时间同日预约、设备可用时段、审批、借还、续约、处罚阶梯。
2. 用户端：工作台 / 仪器预约 / 记录查询；设备分类、项目归属、实际地点动态筛选；日期与时段预约；个人通知。
3. 管理员：独立 /admin 路由与登录入口，设备增改及图片上传、审批、用户违规记录；无公开管理员注册或生产默认密码。
4. 准入：完善条例（标注原文未完整读取），30 道选择题中随机抽 10 道，100 分满分合格。生产端保管正确答案，注册前校验一次性合格凭证，强制用户角色。
5. 数据服务：数据库迁移、存储策略、测试数据库下真实执行 RPC 和角色越权测试。活动预约串行锁，重复提交冲突；续约为相邻的新审批单，不提前更改原预约。
6. 交付：GitHub Actions Pages 部署配置、中文部署与管理员初始化说明、浏览器检查和移动端检查。无仓库/服务配置时交付可运行代码与演示预览，明确未上线。

默认决策：北京时间；每日可约窗口由设备配置；预约至少 30 分钟并按半小时对齐；100 分满分准入；管理员审批后才能使用；取消、归还和处罚留记录；不自动操控实体门禁。

已知来源限制：学校网站公开列表可访问；腾讯文档只读取到机器人标题等目录，专有开关机和调试步骤不得据此虚构。
